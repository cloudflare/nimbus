With `agents: { mcp: true }`, the site serves a remote [MCP](https://modelcontextprotocol.io/) server at `/mcp`. Any MCP client that speaks Streamable HTTP can connect, without a key, and read the documentation through two tools: `list_pages` and `get_page`. The server runs inside the site's own server output, so there is nothing else to deploy.

The server reads what the build already publishes: the pages and Markdown versions behind `llms.txt` and site search. There is no search tool; agents list pages and read them, or fetch `llms.txt` and the `.md` URLs directly.

## Turn it on

The server needs a server adapter, because `/mcp` answers requests at run time. If the site is static, add the adapter for the host you deploy to: `cloudflare`, `netlify`, `node` or `vercel`. For a Node server:

<PackageManagers pkg="@cloudflare/nimbus-docs" type="exec" args="add adapter-node" />

On a site with no `rendering` policy, `add adapter-cloudflare` also sets `rendering: { default: "request" }`, so docs and API pages render on request. The server doesn't need that: to keep them prerendered, set `rendering: { default: "build" }`. The server itself only needs `/mcp` and its card on request.

Install the MCP server SDK in the project. It is an optional dependency of Nimbus: sites without the server never install it.

<PackageManagers pkg="@modelcontextprotocol/server@2" />

Then turn the server on in the Nimbus config:

```ts title="astro.config.ts"
const nimbusConfig = defineNimbusConfig({
  site: "https://docs.example.com",
  title: "Example",
  agents: { mcp: true },
});
```

A build with `agents.mcp` and no server adapter, or without the SDK installed, stops with a message that says what to add; `nimbus-docs check` reports both before a build.

To turn it off, set `agents.mcp` to `false`: `/mcp`, the card and the Copy MCP URL action go away. You can then remove `@modelcontextprotocol/server`, and the adapter if nothing else on the site renders on request.

## Try it locally

`astro dev` serves `/mcp`, without an adapter, from the last content sync. List the tools with the MCP Inspector, at the address `astro dev` prints, with the `base` path, and as `/mcp/` under `trailingSlash: "always"`:

<PackageManagers pkg="@modelcontextprotocol/inspector" type="dlx" args="--cli http://localhost:4321/mcp --transport http --method tools/list" />

To try the production build, run it the way the adapter runs in production: on Node, `node dist/server/entry.mjs` (set `HOST` and `PORT`), which serves `dist/client` next to it; on Cloudflare, `wrangler dev`. The URLs the server returns, and the one the Copy MCP URL action copies, are built from `site`, not from the address you requested; point the client at the local address yourself.

## What the site serves

| Path | What it is |
| --- | --- |
| `/mcp` | The server. `POST` a JSON-RPC message; each answer is one `application/json` body, and a notification gets `202`; `GET` and `DELETE` answer `405`, since the server is stateless and keeps no sessions. A `POST` whose `Content-Type` isn't `application/json`, or a `DELETE` without a `Content-Type`, from anywhere but the site's own `Origin` gets Astro's origin-check `403` instead. `OPTIONS` answers the browser preflight. |
| `/mcp/server-card` | The [Server Card](https://github.com/modelcontextprotocol/ext-server-card): the server's name, the installed Nimbus version, a description and the endpoint URL, served on request as `application/mcp-server-card+json` with `Access-Control-Allow-Origin: *`, cacheable for five minutes (`Cache-Control: public, max-age=300, s-maxage=300`). |

The card is listed in `/.well-known/ai-catalog.json` (unless `agents.discovery` is `false`), and `llms.txt` names the endpoint, so agents that start from either find the server. The server's name is the site's hostname reversed plus `/docs`: `docs.example.com` becomes `com.example.docs/docs`. A site on `localhost` or an IP address is `local.nimbus/docs`.

Under a `base`, both paths sit under it: `https://docs.example.com/docs/mcp`. With `trailingSlash: "always"` the paths are `/mcp/` and `/mcp/server-card/`. Use exactly that form: `astro dev` answers the other with `404`, and a production server may redirect it. The Node adapter redirects with a `301`, which clients follow as a `GET`, so the server answers `405`. Redirects also carry no CORS headers. The card, `llms.txt` and the Copy MCP URL action all give the right form.

A page, content entry or public file at either path fails the build, since the server would hide it.

## The tools

**`list_pages`** returns pages with their `title`, `url`, `markdownUrl` and `section`, plus `description` and `version` when the page has them, 200 at a time. Pass `nextCursor` back as `cursor` for the next page. Filter by `section`, the first path segment (`guide` for `/guide/install/`; a root content page is `index`), or by one `version` from the site's [`versions`](/configuration#site-config) manifest, the docs versions that `nimbus-docs add new-version` sets up. A `version` filter returns that version's docs pages only; pages outside the docs versions, such as a blog or an API reference, have no version and appear in the unfiltered list.

```json
{ "section": "guide" }
```

**`get_page`** returns one page as Markdown: `{ "title", "url", "markdownUrl", "content" }`. Pass the `url` that `list_pages` returned, or a site-relative path such as `/guide/`; only the path of an absolute URL is used. Pages over about 100,000 characters are cut with `"truncated": true`; the `markdownUrl` serves the whole page.

```json
{ "url": "https://docs.example.com/guide/" }
```

Both tools return their result as JSON in a text content block. They return errors in the result, with `isError` set. Arguments that don't match the tool's schema get the MCP SDK's validation message. Other errors are `{ "error": { "code", "message" } }`, with the code `invalid_input` (an unknown version, or a cursor from other filters), `not_found` (no published page at that URL) or `unavailable` (the site's published files couldn't be read).

## Which pages

The tools see the pages that have a Markdown version: collections made with `docsCollection()` and `apiCollection()`, in every rendering mode. A collection defined by hand with Astro's `defineCollection` has no Markdown version and is not listed, the same as in `llms.txt`.

By default `list_pages` matches site search: pages with `noindex: true` are left out unless they set `searchable: true`, and deprecated versions are left out unless you ask for one by `version`. Hidden versions and drafts are never listed and never served. `get_page` also reads `noindex` pages by URL, and resolves an API URL with `?version=` to the default version, which is the one with a Markdown version.

A homepage made in `src/pages` instead of a content entry isn't a page here: `get_page` with `/` finds nothing, and `/index.md` serves the `llms.txt` index instead.

## Connect a client

Give the client the endpoint URL using its own remote MCP setup instructions. Configuration formats differ between clients.

The starter's docs layout shows a **Copy MCP URL** page action whenever the server is on. Clicking it copies the endpoint URL and briefly changes the label to **Copied**.

A site made before the action existed can add the two starter files:

<PackageManagers pkg="@cloudflare/nimbus-docs" type="exec" args="diff src/components/ConnectMcp.astro --apply" />

<PackageManagers pkg="@cloudflare/nimbus-docs" type="exec" args="diff src/components/connect-mcp.client.ts --apply" />

`diff` needs a site on a released version. Otherwise, copy both files from a newly scaffolded site.

Then in `src/layouts/DocsLayout.astro`, pass it to `PageActions`, which renders it after its own actions:

```astro title="src/layouts/DocsLayout.astro"
---
import ConnectMcp from "@/components/ConnectMcp.astro";
import { capabilities } from "virtual:nimbus/agent-capabilities";
---

<PageActions markdownUrl={markdownUrl} lastUpdated={lastUpdated} class={description ? undefined : "mt-3"}>
  {capabilities.mcpUrl && <ConnectMcp />}
</PageActions>
```

The guard keeps the action's script off sites without the server. A `PageActions` copied before the slot existed doesn't render children: update it with `nimbus-docs add page-actions --overwrite`, or keep `<ConnectMcp />` after it.

## Limits and safety

The server is read-only and public: it serves what the site already publishes, with `Access-Control-Allow-Origin: *` so browser-based clients can connect. A request with a malformed or `null` `Origin` header is refused with `403`, and a body over 64 KB with `413`. There is no authentication; private documentation stays behind your own access control, as with the rest of the site.

Rate limiting is the host's job: add a rule for the `/mcp` path in its firewall, or in a proxy in front of the site. The server itself does none.

## Adapters

Nimbus tests the server on the Node and Cloudflare adapters. On Node it reads the published Markdown from the deployed `dist/client` directory; on Cloudflare, through the site's asset binding. Other adapters work when the server can read `dist/client`, or fetch it from the site's own URL; verify a `tools/call` on the deployed site. A preview deployment behind access protection, such as Vercel's, answers that fetch with `401`, and the tools report `unavailable`.

With the server on, the server bundle carries the MCP SDK, about 140 KB gzipped, loaded the first time `/mcp` is called.
